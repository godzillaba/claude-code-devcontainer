# CLAUDE.md

A personal Docker Sandbox (`sbx`) template for Claude Code. One image, `template/Dockerfile`,
extending `docker/sandbox-templates:claude-code-docker`. No kit.

## Conventions

- Base is Ubuntu 26.04, user `agent` (home `/home/agent`, `WORKDIR /home/agent/workspace`).
  It already has `claude`, `gh`, Docker, `git`, `curl`, `node`, `uv`, `rg`, `jq`, `go` — don't
  reinstall. Don't override `ENTRYPOINT`/`CMD` (base runs `claude --dangerously-skip-permissions`).
- Install system tools as `root`, user tools as `agent`. Pin versions, digests where available.
- Build host may be arm64 (Apple Silicon). Downloaded binaries must be arch-correct — select by
  `dpkg --print-architecture` or build from source (`solc`, `gambit`, `esk`). `command -v` isn't
  enough; the test must actually run each binary.
- `~/.claude/settings.json` is regenerated by sbx each create, so the MCP deny-list + hooks live
  in `/etc/claude-code/managed-settings.json`. Git config goes in `~/.config/git/config`.
- Network allow-list and secrets are host-side (`sbx policy` / `sbx secret`), never baked.

## Test

`sbx` is host-only (can't run inside a sandbox), but Docker-in-Docker can — so validate the image
directly: build it, then run it as a plain container and check tools + config resolve.

```bash
docker build -t claude-sbx:test template/
# Run the arch-sensitive binaries (not just `command -v`) — this is what catches
# x86-only downloads failing on arm64. Add config checks as needed.
docker run --rm --entrypoint bash claude-sbx:test -c \
  'solc --version && gambit --help >/dev/null && forge --version && esk --help >/dev/null && \
   cast to-wei 1 ether && jq -e .permissions.deny /etc/claude-code/managed-settings.json >/dev/null && echo OK'
```

Covers everything except the sbx lifecycle (`sbx run`/`policy`/`secret`), which needs the host.
